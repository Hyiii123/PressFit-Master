## 2. 架构设计：Clean Architecture 与依赖倒置

### 核心分层（5 个独立工程）
1. **`PressFit.Core`（核心领域层）**：
   - **特点**：零第三方依赖（纯 POCO 模型、枚举、算法接口、用户角色）。
   - **价值**：业务逻辑与具体的通信库（如 Modbus、S7）或数据库（SQLite、MySQL）完全解耦。
2. **`PressFit.Communication`（通信协议层）**：
   - 封装原生 Socket Modbus TCP 客户端、MBAP 报文编解码器、自愈重连状态机、Channels 异步数据管道。
3. **`PressFit.Data`（数据持久层）**：
   - 基于轻量微 ORM `Dapper` + `Microsoft.Data.Sqlite`，开启 WAL 模式，集成 CSV 导出。
4. **`PressFit.Simulator`（数字孪生仿真层）**：
   - 原生 `TcpListener` 模拟 Modbus Slave 从站，提供带高斯白噪声的伺服压装 S 曲线与 6 类故障注入。
5. **`PressFit.UI`（人机交互展现层）**：
   - WPF 现代化暗色工业大屏，MVVM 模式（CommunityToolkit.Mvvm），提供 60FPS 实时曲线、配方管理窗口、历史追溯与 SPC 钟形图分析。

## 3. 并发与性能：Channels 管道与零 GC 抖动

### 传统上位机卡顿根因
传统上位机如果在 50Hz~100Hz 的采集线程中直接调用 `Dispatcher.Invoke(() => ObservableCollection.Add(new Point()))`：
- **线程抢占**：大量短频上下文切换导致 WPF UI 线程被淹没，界面掉帧、按钮卡顿。
- **内存碎片**：每个点如果都是 `class` 对象，每秒产生数百个小对象，迅速填满 GC Gen 0 并触发 GC 停顿（STW）。

### 本项目的架构破局
1. **单写单读有界通道**：
   ```csharp
   var options = new BoundedChannelOptions(20000) {
       FullMode = BoundedChannelFullMode.DropOldest, // 极端拥塞时丢弃老点，绝不阻塞采集
       SingleWriter = true,
       SingleReader = true
   };
   _channel = Channel.CreateBounded<PressPoint>(options);
   ```
2. **值类型零堆分配**：
   采样点采用 `readonly record struct PressPoint(double Displacement, double Force, double TimestampMs)`，大小仅 24 字节，直接在栈和连续环形内存流转，零堆分配。
3. **消费者批量定频抽帧 (60FPS)**：
   消费端定时批量抽取 64 点批次（Batch），以约 16ms 节奏局部重绘，彻底杜绝掉帧与 GC 抖动。

## 4. 网络与通讯：Modbus TCP 协议与自愈看门狗

### MBAP 报文头结构（7 字节大端格式）
| 字节偏移 | 字段名 | 长度 | 说明 |
| :--- | :--- | :--- | :--- |
| 0 ~ 1 | Transaction ID (事务元标识) | 2 Bytes | 自增序列号，用于请求-响应配对 |
| 2 ~ 3 | Protocol ID (协议标识) | 2 Bytes | 固定为 `0x0000`（代表 Modbus 协议） |
| 4 ~ 5 | Length (后随字节长度) | 2 Bytes | 从单元 ID 起算到报文尾的总字节数 |
| 6 | Unit ID (从站单元号) | 1 Byte | 通常设为 `1` |

### 粘包与半包解决方案
- 充分利用 MBAP 头中已明确给出 `Length` 的特性；
- 采用**“两阶段定长状态机流式读取”**：
  1. 先严格调用 `ReadExactBytesAsync(header, 0, 7)` 读取 7 字节头部；
  2. 解析出 `length`，再次循环调用 `ReadExactBytesAsync(pdu, 0, length - 1)` 直至读满精确字节；
  3. 从根本上杜绝了 Socket 粘包与截断半包。

### 四状态自愈看门狗与指数退避算法
- 状态机：`Disconnected` ➔ `Connecting` ➔ `Connected` ➔ `Degraded`。
- **指数退避重连**：断线后延时间隔按 $2^{\min(failures, 4)}$ 秒递增（1s, 2s, 4s, 8s, 16s），防止断网时死循环猛烈重试造成工控机 CPU 飙升与网络风暴。

## 5. 算法体系：位移-压力包络线 (Envelope) 与 SPC CPK 分析

### 为什么只看峰值压力不行？
- **虚压漏判**：工件未放置或配合极松，压头压到底才受阻，峰值可能符合，但全程大部分为空压；
- **过盈刮伤**：中间因毛刺或倾斜卡滞导致中间压力陡增，但最终到达设定深度，成品内部已有裂纹。

### 全行程包络线 (Envelope) 算法设计
1. 建立非线性渐进抗力理论基准曲面：$F(s) = F_0 + \Delta F \cdot (progress^{1.25})$；
2. 设定上下包络公差窗口：$F_{upper}(s) = F_{ref}(s) \cdot (1 + Margin\%) + 0.5$，$F_{lower}(s) = F_{ref}(s) \cdot (1 - Margin\%) - 0.5$；
3. 全行程扫描采样点是否击穿上下限，判定耗时 `< 5ms`。

### SPC (统计过程控制) 与 CPK 制程能力分析
- **样本均值 $\mu$ 与样本标准差 $\sigma$**（Bessel 修正，除以 $N-1$）；
- **过程能力 $Cp$**：$Cp = \frac{USL - LSL}{6\sigma}$（衡量数据离散度）；
- **制程能力指数 $Cpk$**：考虑均值偏移：$Cpu = \frac{USL - \mu}{3\sigma}$，$Cpl = \frac{\mu - LSL}{3\sigma}$，$Cpk = \min(Cpu, Cpl)$；
- **工业判定标准**：
  - $Cpk \ge 1.67$：A+ 特级，状态极优；
  - $1.33 \le Cpk < 1.67$：A 优秀，符合车企外审验收标准；
  - $1.00 \le Cpk < 1.33$：B 警戒，需严加监控；
  - $Cpk < 1.00$：C 不足，次品率高，必须整改停机。

- **操作员 (Operator)**：免密操作，仅允许扫码、换批次、启动与急停，配方编辑按钮置灰拦截；
- **工艺工程师 (Engineer)**：密码 `1234`，允许进入配方标定控制台修改压深、公差带与速度；
- **系统管理员 (Administrator)**：密码 `8888`，最高系统级维护权限。

### Modbus 0x10 一键参数下发
- 工艺员调整完参数后，无需下位机工程师在 PLC 梯形图里硬编码；
- 点击“一键下发”，上位机自动调用 **Modbus 0x10 (Write Multiple Registers)** 功能码，将标定数据批量推入保持寄存器 10~12，并自动回显对账。

## 7. 数据持久化：SQLite WAL 模式与 Dapper 异步批量落盘

### 为什么选择 SQLite 而不是 MySQL / SQL Server？
- 工位机常运行在无外网车间的工控机上，单文件 SQLite 零配置、零服务挂掉风险，非常适合作为单工位黑匣子存储。

### 高并发写库不卡顿秘诀：WAL 预写日志模式
- 默认回滚日志模式（Rollback Journal）在写事务时会加排他锁阻塞查询；
- 在数据库初始化时执行：
  ```sql
  PRAGMA journal_mode = WAL;
  PRAGMA synchronous = NORMAL;
  ```
- **原理**：写操作追加写入 `.wal` 文件，读操作直接读取主库，**读写完全并发互不阻塞**。配合 Dapper 微 ORM，落盘延迟压制在 3ms 以内。

## 9. 高频核心面试题 15 问与一击必杀标准回答

### Q1: 你手头没有真实设备，你怎么保证你这个系统是有用的？
> **答**：工业通讯在网线接口处是**字节级透明**的。只要下位机遵循标准 Modbus TCP 规范（相同的 MBAP 头、0x03/0x10 功能码、大端字节序），对端是真实 PLC 还是虚拟从站没有任何差异。部署时只需将 IP 改为车间物理 IP 即可无缝上线。此外，我自研的仿真器具备弹塑性动力学拟合和故障注入能力，能提前做 100% 的边界测试与破坏性测试，这在现场真机上反而是做不到的。

### Q2: 现场采样频率达到 100Hz，实时在 WPF 画线界面为什么不卡？
> **答**：因为我实现了**高频采集与 UI 渲染彻底解耦**。后台采集线程只负责向 .NET 8 的 `System.Threading.Channels` 有界管道推入值类型 `PressPoint` 结构体，零堆内存分配；UI 端定时以 60FPS（约 16ms）批量抽取点集进行局部重绘，绝不使用 `Dispatcher.Invoke` 逐点打扰主线程，因此 CPU 占用率常年稳定在 3% 以内。

### Q3: 现场发生强电磁干扰导致网络偶发断开，你的软件怎么处理？
> **答**：我设计了**自愈式通信看门狗**与**指数退避重连机制**。当心跳检测异常时，通信客户端自动进入降级重试状态，重试间隔自适应延长（1s ➔ 2s ➔ 4s ➔ 8s ➔ 16s），避免惊群网络风暴。一旦网线重新插好或干扰消除，看门狗在下一轮心跳自动完成握手并自愈恢复。

### Q4: 质检员发现某批次零件在客户现场坏了，你的上位机怎么支持质量追溯？
> **答**：系统提供独立的“生产追溯与曲线复盘系统”。每件产品的条码、最大压力、终点位移以及全过程采样曲线（JSON 序列化）均已归档 SQLite。品保人员只需输入条码，系统能 1:1 完整重现当时压装的位移-压力物理曲线，并叠加包络线公差带，准确查看是哪一个毫秒、哪一个位移点发生了超限。同时支持一键导出符合车间标准的 CSV 质检报表。

### Q5: 为什么不用成熟的工业组态软件（比如 WinCC、InTouch），而要自己用 C# 开发？
> **答**：传统组态软件开发通用监控画面很快，但遇到复杂的**高频曲线算法判定（如全行程包络线分析、SPC Cpk 实时高斯拟合）、与专机算法深度交互、定制化本地轻量数据库存储及现代扁平暗色工业大屏**时，组态软件的二次开发成本极高且性能受限。C# WPF 能够提供极高的自主可控性、底层优化空间与更好的用户交互体验。
