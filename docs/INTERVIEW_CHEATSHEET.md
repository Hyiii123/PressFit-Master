## 3. 并发与性能：Channels 管道与零 GC 抖动

### 传统上位机卡顿根因
传统上位机如果在 50Hz~100Hz 的采集线程中直接调用 `Dispatcher.Invoke(() => ObservableCollection.Add(new Point()))`：
- **线程抢占**：大量短频上下文切换导致 WPF UI 线程被淹没，界面掉帧、按钮卡顿。
- **内存碎片**：每个点如果都是 `class` 对象，每秒产生数百个小对象，迅速填满 GC Gen 0 并触发 GC 停顿（STW）。

### 本项目的架构破局
1. **单写单读有界通道**：
   ```csharp
   var options = new BoundedChannelOptions(20000) {
       FullMode = BoundedChannelFullMode.DropOldest, // 极端拥塞时丢弃老点，绝不阻塞采集
       SingleWriter = true,
       SingleReader = true
   };
   _channel = Channel.CreateBounded<PressPoint>(options);
   ```
2. **值类型零堆分配**：
   采样点采用 `readonly record struct PressPoint(double Displacement, double Force, double TimestampMs)`，大小仅 24 字节，直接在栈和连续环形内存流转，零堆分配。
3. **消费者批量定频抽帧 (60FPS)**：
   消费端定时批量抽取 64 点批次（Batch），以约 16ms 节奏局部重绘，彻底杜绝掉帧与 GC 抖动。

## 4. 网络与通讯：Modbus TCP 与西门子 S7 双核心驱动

### 西门子 S7-1200/1500 协议深度原理
- **底层承载**：基于 **ISO-on-TCP (RFC 1006)** 协议，标准端口 **`102`**；
- **两阶段握手协议流程**：
  1. **COTP 连接建立**：客户端发送 Connection Request (CR)，携带源 TSAP 与目的 TSAP（由机架号 Rack 与槽位号 Slot 动态计算：`0x0100 + Rack*0x20 + Slot`，S7-1200/1500 槽位号通常为 1）；
  2. **S7 通信协商**：发送 Setup Communication PDU，协商 PDU 最大长度（默认 480 字节）与最大并行任务数；
  3. **数据读写 (S7 Any Pointer)**：
     - Area 区域标识符：`0x84` 代表 DB 数据块；
     - 地址偏移量采用 3 字节 Bit Offset（例如 DBW10 对应 `10 * 8 = 80` 位偏移）；
     - 数据解析严格按照西门子 **大端字节序 (Big-Endian)** 提取。

## 5. 容灾与同步：边缘离线存储与断点补传 (Store-and-Forward)

- **现场痛点**：车间网络抖动或工厂 MES 服务器停机升级时，工位若无法上报数据，极易发生丢单断号；
- **系统架构**：
  1. 上位机压装完成，生产记录**率先异步落盘本地 SQLite WAL 数据库**，初始标记 `IsSyncedToMes = false`；
  2. 独立后台服务 `MesSyncWorker` 持续探测云端/MES 接口连通性；
  3. 网络恢复后，流水线以每批 10 件节奏自动提取未同步数据，无感补发，补发成功后原子更新 `IsSyncedToMes = true`；
  4. 实现生产现场的**“零丢包 (Zero Data Loss) 高可靠容灾体系”**。

## 6. 质量与精益：位移-压力包络线、SPC CPK 与工业 OEE 看板

### 全行程包络线 (Envelope) 算法设计
1. 建立非线性渐进抗力理论基准曲面：$F(s) = F_0 + \Delta F \cdot (progress^{1.25})$；
2. 设定上下包络公差窗口：$F_{upper}(s) = F_{ref}(s) \cdot (1 + Margin\%) + 0.5$，$F_{lower}(s) = F_{ref}(s) \cdot (1 - Margin\%) - 0.5$；
3. 全行程扫描采样点是否击穿上下限，判定耗时 `< 5ms`。

### SPC (统计过程控制) 与 CPK 制程能力分析
- **过程能力 $Cp$**：$Cp = \frac{USL - LSL}{6\sigma}$（衡量离散度）；
- **制程能力指数 $Cpk$**：$Cpk = \min\left(\frac{USL - \mu}{3\sigma}, \frac{\mu - LSL}{3\sigma}\right)$；
- 评定标准：$Cpk \ge 1.33$ 达到车企外审验收标准，系统动态绘制正态分布钟形曲线。

### 工业 OEE (综合设备效率) 黄金三角
- **时间稼动率 (Availability)**：实际运行时间 / 计划开机时间；
- **性能稼动率 (Performance)**：(标准节拍 $\times$ 实际产出) / 实际运行时间；
- **质量指数 (Quality)**：合格品数量 / 总产出数量；
- **综合效率**：$\text{OEE} = A \times P \times Q$（世界级标杆为 $\ge 85\%$）；
- **精益经济核算**：实时统计当班总产值（$OK \times 单价$）、报废损失（$NG \times 扣罚$）与净生产收益。

## 7. 报警管理：ISA-18.2 报警生命周期与风暴抑制

### 工业 ISA-18.2 标准报警四态机
```text
[正常 Normal] ──(触发故障)──► [活动·未确认 Active Unack]
                                      │
                               (操作工点击确认 Ack)
                                      ▼
[消除·未确认 Cleared Unack] ◄── [活动·已确认 Active Ack]
          │                                   │
          │                               (故障消除)
          ▼                                   ▼
[正常归档 Normal] ◄──────────────(操作工确认)─┘
```
- **报警风暴抑制**：同类未恢复报警去重过滤，不重复落库与打扰 UI；
- **交互设计**：主界面活动悬浮条强提醒、未确认红点角标与全生命周期落库审计。

## 11. 高频核心面试题 22 问与一击必杀标准回答

### Q1: 西门子 S7 通信协议的 DB 块寻址原理是什么？S7-1200 和 1500 的机架号和槽位号怎么配？
> **答**：西门子 S7 协议基于 ISO-on-TCP (RFC 1006) 封装，标准端口为 102。连接时首先通过 COTP 报文携带 TSAP 进行握手。对于 S7-1200 和 S7-1500，机架号 Rack 通常为 `0`，CPU 槽位号 Slot 通常为 `1`（老款 S7-300 则为 `2`）。在读取数据块时，Area 区域标识符为 `0x84`（代表 DB 块），地址偏移量以 **Bit 为单位编码**（例如 DBW10 对应 $10 \times 8 = 80$ 的位偏移）。接收到的字节流严格按照西门子 **大端字节序 (Big-Endian)** 解析。我在系统中抽象了 `IIndustrialPlcDriver` 驱动接口，上层应用无需关心对端是 Modbus 还是西门子 S7。

### Q2: 什么是工业 OEE？你在上位机中是如何量化设备综合效率和经济效益的？
> **答**：OEE（综合设备效率）是衡量产线精益制造水平的国际黄金指标，由三大要素相乘得出：$\text{OEE} = \text{时间稼动率 (A)} \times \text{性能表现 (P)} \times \text{质量指数 (Q)}$。我在上位机中结合配方标准节拍，实时计算了有效运行时间、节拍损失率与成品合格率，并依据国际标准划定评级（$\ge 85\%$ 为世界级卓越产线）。同时我将精益指标与财务核算打通，在看板上实时展示“当班总产值（$OK \times 单价$）减去报废损失（$NG \times 扣罚$）”，直观体现工位的净经济收益。

### Q3: 车间内网或 MES 系统断网 10 分钟，你的上位机怎么保证压装数据不丢失并自动补传？
> **答**：我设计了**边缘离线存储与断点补传（Store-and-Forward）架构**。压装完成时，系统率先将完整时序数据异步持久化到本地 SQLite WAL 数据库，初始标记为未同步状态（`IsSyncedToMes = false`）。独立后台工作线程持续监控云端接口心跳；一旦内网恢复，工作线程自动采用小批量流水线机制无感补传，补传成功后更新同步时间戳。这样即便现场持续断网，本地也能安全缓存数万条记录，彻底消除丢包隐患。

### Q4: WPF 项目中如何优雅地实现多语言动态切换而不需要重启软件？
> **答**：我在 WPF 中采用了**动态合并资源字典（MergedDictionaries）热替换**方案。将中文与英文文案分别封装为 `Strings.zh-CN.xaml` 和 `Strings.en-US.xaml`。当用户点击切换语言时，后台直接将当前应用的旧语言字典移除，并动态注入目标语言字典；界面上所有控件采用 `{DynamicResource Key}` 动态资源绑定，无需关闭或重启主窗体，全屏界面在几毫秒内即可无缝完成中英文切换。

### Q5: 现场采样频率达到 100Hz，实时在 WPF 画线界面为什么不卡？
> **答**：因为我实现了**高频采集与 UI 渲染彻底解耦**。后台采集线程只负责向 .NET 8 的 `System.Threading.Channels` 有界管道推入值类型 `PressPoint` 结构体，零堆内存分配；UI 端定时以 60FPS（约 16ms）批量抽取点集进行局部重绘，绝不使用 `Dispatcher.Invoke` 逐点打扰主线程，因此 CPU 占用率常年稳定在 3% 以内。

### Q6: 工业现场发生报警时，为什么不能只打一行日志？ISA-18.2 标准是什么？
> **答**：工业现场报警直接关系到设备寿命和人身安全。遵循 ISA-18.2 标准，报警必须具有‘触发 ➔ 人工确认 (Ack) ➔ 物理恢复 (Clear)’的全生命周期闭环。我们在上位机中设计了**活动悬浮条强提醒、未确认红点角标与必须人工确认机制**，所有确认人与时间戳落盘审计，杜绝操作工遗漏严重故障。

### Q7: 你手头没有真实设备，你怎么保证你这个系统是有用的？
> **答**：工业通讯在网线接口处是**字节级透明**的。只要下位机遵循标准 Modbus TCP 或西门子 S7 规范，对端是真实 PLC 还是虚拟从站没有任何差异。部署时只需将 IP 改为车间物理 IP 即可无缝上线。此外，我自研的仿真器具备弹塑性动力学拟合和故障注入能力，能提前做 100% 的边界测试与破坏性测试，这在现场真机上反而是做不到的。
